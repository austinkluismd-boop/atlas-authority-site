# atlas-authority-site — session laws

The public Atlas Authority™ site on GitHub Pages (`www.atlas-authority.com`,
CNAME committed). Two surfaces live here:

- `/` — the marketing page (`index.html`). Self-contained: fonts embedded as
  data URIs, zero external fetches at view time. Keep it that way.
- `/command/` — **Atlas Command**, the practice's live estate console for
  TSA + OSA. Noindexed and excluded in `robots.txt`; it is an operating
  surface, not marketing.

## Command console laws (inherited from the estate)

1. **Provenance/label law.** A figure renders as MEASURED only when its
   provenance is `measurement`. Semrush and every vendor model is
   `estimate`; the console's Authority Index is `demo`. The classes never
   merge into one line or one sentence.
2. **A gap is not a zero.** Absences are recorded with reasons and rendered
   as broken lines / empty states — never plotted as 0, never invented.
3. **One edit pathway for data.** Figures come from `command/feed.json`,
   built ONLY by `command/build_feed.py` from the seeds in `command/data/`
   plus live API pulls when repo secrets exist (`SEMRUSH_API_KEY`,
   `CRUX_PSI_API_KEY`). Never hand-edit `feed.json`.
4. **`command/data/history.jsonl` is append-only.** The hourly workflow
   (`.github/workflows/command-feed.yml`) appends live observations there;
   nothing ever rewrites or truncates it. That file is the console's
   accumulating time series.
5. **Zero third-party requests at view time.** The console fetches only
   same-origin `feed.json`. No CDNs, no external fonts, no beacons. The one
   sanctioned exception is the estate's OWN concierge API (`CONFIG.conciergeApi`,
   unset until it deploys): it is first-party, it is called only when a
   signed-in person clicks Ask, and never on load. Page load stays
   zero-request in every state — the browser battery asserts it.
6. **Access is per person, by link, never by password.** A person's card
   carries a keyring in the URL **fragment** (fragments never reach a server,
   so tokens stay out of logs and Referer headers); the console stores it in
   that browser, strips it from the address bar, and sends it only to the
   concierge API. The roster and the minting live in practice-stack
   (`tenants/people.json`, `ops/aws/concierge/people.py`) — this repo holds
   no credential and no roster. Signing in unlocks **Ask Atlas**; the figures
   on the page are the estate's shared read-out and are not gated by it
   (OPS-32 covers gating the page itself).
7. **A console change is not done until a browser says so.**
   `command/console_battery.mjs` (Playwright, 27 checks) must pass: every
   view renders, zero console errors, zero third-party requests, and the
   whole sign-in path — link, warm-tab link, paste, expiry, garbage, sign-out.
8. **Baseline is frozen.** `command/data/baseline-index.json` is the
   point-0 pre-registration baseline (schema `atlas-baseline-index-v1`,
   generated by practice-stack `mission-control/tools/index_baselines.py`).
   Refreshing it means regenerating it THERE and copying the output here —
   never editing values in place.

## Seed refresh pathway

`command/data/{ops-queue,engine-coverage,priorities}.json` mirror
practice-stack state (`ops-tasks/tasks.json`, engine coverage, the ranked
priority board). When those change in practice-stack, regenerate the mirrors
in the same change set and note the capture date inside each file.

## Estate map

Siblings: `practice-stack` (platform suite; `docs/SESSIONS.md` there is the
cross-session ledger — log your session), `atlas-engine` (data engine),
`tsa-command-center` (public demo consoles). Every push to `main` here
deploys to Pages.
